# How this server compares with the MCP standards

Checked on 2026-11-04 against spec revision **2026-07-28**. To check again, start at
[What to re-check](#what-to-re-check). "Tested" names the test that proves it; `(e2e)` also needs the lab.

## What the standards are

| Standard | Covers | Applies here |
|---|---|---|
| [MCP specification](https://modelcontextprotocol.io/specification/latest) | The protocol, including what a server must do | Yes |
| [`server.json`](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/server-json/generic-server-json.md) for the [MCP Registry](https://modelcontextprotocol.io/registry/quickstart.md) | Identity, packages, settings | Yes |
| [MCPB](https://github.com/modelcontextprotocol/mcpb) | Packaging a local server for one-click install | Optional, not done |
| [Server Cards, SEP-2127](https://modelcontextprotocol.io/seps/2127-mcp-server-cards.md) | Discovering remote HTTP servers | No: this is stdio, and cards leave tools out on purpose |
| [AGENTS.md](https://agents.md) | Instructions for coding agents | Yes |
| [Agent Skills](https://agentskills.io/home) | Portable instructions | Yes: `skills/nvsentinel-lab` |

**There is no standard for human-written MCP docs.** The spec's own
[docs index](https://modelcontextprotocol.io/llms.txt) has no such page. The common practice is to generate them
from the tool definitions, as the [GitHub MCP server](https://github.com/github/github-mcp-server/blob/main/cmd/github-mcp-server/generate_docs.go)
does and as `make docs` does here. Its [tool snapshots](https://github.com/github/github-mcp-server/blob/main/docs/testing.md)
are the same idea as `docs/tools.json` and the test that fails when it goes stale.

## Protocol

| Requirement | Level | Status | Tested |
|---|---|---|---|
| [`server/discover`](https://modelcontextprotocol.io/specification/2026-07-28/changelog.md) answers versions, capabilities, identity | MUST | Yes, from the SDK | `TestItSpeaksTheLatestProtocol` (e2e) |
| `resultType` on every result, `ttlMs` and `cacheScope` on `tools/list` | MUST | Yes, from the SDK. `ttlMs` is 0, so clients do not cache | same |
| Older revisions, through `initialize` | MAY | Yes, back to 2024-11-05 | every other e2e test |
| [stdout holds only MCP messages](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio.md), logs go to stderr | MUST | Yes | same |
| Exit when stdin closes | SHOULD | Yes. It first finishes a running scenario's reset, up to 6 minutes, on purpose | same; `TestShutdownWaitsForARunningChange` |
| [Stop work on `notifications/cancelled`](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation.md) | SHOULD | Yes | `TestCancellationStopsTheWork` (e2e) |
| Send no reply to a cancelled request | SHOULD on that page, MUST on the stdio page | **No.** The SDK sends one, and clients are told to ignore it. Fixing it belongs in the SDK | Seen on the wire |
| [Deterministic tool order](https://modelcontextprotocol.io/specification/2026-07-28/server/tools.md) | SHOULD | Yes | `TestItSpeaksTheLatestProtocol` (e2e) |
| Unknown tool is a protocol error, bad input is `isError` | Required | Yes | same |
| Structured results also come as text | SHOULD | Yes | same |
| Do not add deprecated [logging](https://modelcontextprotocol.io/specification/2026-07-28/deprecated.md) | SHOULD NOT | Yes: the SDK's default is overridden | `TestOnlyToolsAreAdvertised` |
| Advertise `listChanged` only if the list changes | Implied | Yes: it never changes | same |

## Security

| [Requirement](https://modelcontextprotocol.io/specification/2026-07-28/server/tools.md#security-considerations) | Level | Status | Tested |
|---|---|---|---|
| Validate all tool inputs | MUST | Yes | `TestBadArgumentsAreRefusedAndNeverReachTheCluster` |
| Access controls | MUST | Yes: changes off by default, kind only, least-privilege RBAC | `docs/security.md` |
| Rate limit tool invocations | MUST | Yes: 10 per second, burst of 20 | `TestToolCallsAreRateLimited` |
| Sanitize tool outputs | MUST | Yes: fenced, cleaned, capped | `TestATextCannotCloseItsFence` |
| [Use stdio for a local server](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices.md) | SHOULD | Yes | No listener in the code |
| OAuth, token audience, SSRF, sessions | | Do not apply: no HTTP, no OAuth | |

## Not done or not tested

- **Published to the MCP Registry:** `server.json` is ready. It needs `mcp-publisher` and your GitHub login.
- **[MCP Inspector](https://modelcontextprotocol.io/docs/2026-07-28/tools/inspector.md):** not run. To try it:
  `npx @modelcontextprotocol/inspector --cli nvidia-nvsentinel-mcp --method tools/list`
- **[Conformance suite](https://github.com/modelcontextprotocol/conformance):** not run. Its server mode takes a
  `--url`, so it needs an HTTP server, and this one has no listener by design. The raw e2e tests above check the
  same points that apply to a tools-only stdio server, but they are this repo's own tests, not the official suite.
- **MCPB bundle:** not built. The Registry has no package type for a plain binary, so the image is what it would list.
- **Other MCP clients:** only Claude Code and the Go SDK's client have been used.
